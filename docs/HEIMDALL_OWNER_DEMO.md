# Try Heimdall on your computer

This is a private practice run for the business-registration conversation. It uses the existing Heimdall login, startup guide, conversation history, Loki review and Mimir retrieval. All example decisions are synthetic. Use invented names and references. The professional shortlist is for research and does not verify credentials, fees or availability.

## Start it in VS Code

You need your Valhalla checkout on the draft branch, the Python environment used by the Valhalla API, and the native PostgreSQL tools installed on the computer. The launcher does not connect to an existing PostgreSQL service or a Docker container.

1. Open the Valhalla folder in VS Code. Open **Terminal → New Terminal**.
2. If the checkout already has the Valhalla Python environment, run this in the Windows PowerShell terminal:

   ```powershell
   .\.venv\Scripts\python.exe scripts\launch_heimdall_demo.py
   ```

   If you have not set that environment up yet, use Python 3.11 and run the following once:

   ```powershell
   py -3.11 -m venv .venv
   .\.venv\Scripts\python.exe -m pip install -r services\api\requirements.txt
   ```

   If the launcher cannot find PostgreSQL, provide the **bin** folder from your native PostgreSQL installation. Replace the example folder with the one on your computer:

   ```powershell
   .\.venv\Scripts\python.exe scripts\launch_heimdall_demo.py --pg-bin "C:\Program Files\PostgreSQL\16\bin"
   ```

   On Linux or macOS, use the checkout's Python interpreter and forward slashes. If `initdb` is outside PATH, pass its containing directory with `--pg-bin`. Run PostgreSQL as your ordinary desktop user.

3. Wait for **HEIMDALL DEMONSTRATION**. Open **http://127.0.0.1:8765/demo/** on the same computer. If that port is busy, add `--port 8766` and use the address shown in the terminal.
4. Sign in with the displayed demo email and one-run password. Leave that terminal open.

## What to try

- Choose **Start walkthrough**. Heimdall will show the eight stages from choosing a name and route through a separate launch approval.
- Choose **Review shortlist**. You can inspect the four research leads and the checks still needed before any outreach.
- Choose **Record next stage as practice**. This records a synthetic checkpoint and advances the walkthrough. Repeat through the eight stages to see the final review step. Even after the final entry, activation stays disabled.
- Choose **Read Loki evidence**. It shows a stored receipt generated by the existing local analyst for the synthetic Mimir report.
- Choose **Recall Mimir note**. Heimdall retrieves a synthetic teaching note as provisional evidence. Choose **Sign out**, sign back in with the same one-run password, and select **Show saved progress** to verify that the database retained your practice entries.

## Stop it

Select **Sign out**, return to the VS Code terminal, and press **Ctrl+C**. Wait for the shutdown message. The launcher stops the API and PostgreSQL and removes the disposable database. Starting it again creates a blank demo with a new password. Keep actual incorporation and professional records in your separate authorized process.
