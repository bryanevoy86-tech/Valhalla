## CORE MODELS (NEW)

### 1. ExecutionCase
**Purpose:** Track the complete execution lifecycle of a single opportunity from intake to close

**Model Location:** `services/api/app/models/execution_case.py`

**Fields:**

| Field | Type | Required | Default | Purpose |
|-------|------|----------|---------|---------|
| id | Integer | PK | Auto | Unique case identifier |
| intake_id | Integer | Yes | - | FK to LeadIntake |
| assessment_id | Integer | No | None | FK to UnderwriterAssessment |
| case_type | String(50) | Yes | "unknown" | Classification: real_estate \| business \| arbitrage \| jv \| unknown |
| route_target | String(100) | Yes | "" | Pipeline route: wholesale_pipeline \| fnh_pipeline \| buy_hold_pipeline \| arbitrage_pipeline \| review_pipeline |
| current_stage | String(50) | Yes | "intake" | Stage: intake \| classification \| assessment \| routing \| tasks_created \| execution \| closed \| blocked |
| current_status | String(50) | Yes | "pending" | Status: pending \| in_progress \| blocked \| completed \| archived |
| safe_mode | Boolean | Yes | False | If true, operator must approve next major step |
| blocked | Boolean | Yes | False | If true, execution is halted |
| blocker_reason | Text | No | None | Human-readable reason for block |
| next_action | Text | No | None | Clear instruction for what operator should do next |
| created_at | DateTime | Yes | now() | Creation timestamp |
| updated_at | DateTime | Yes | now() | Last update timestamp |
| created_by | String(100) | No | "system" | User/system that created case |
| updated_by | String(100) | No | "system" | User/system that last updated case |

**Relationships:**
- ← LeadIntake.case_id (one-to-one)
- ← UnderwriterAssessment.case_id (one-to-one, optional)
- ← ExecutionTask (many, via case_id)
- ← ExecutionEvent (many, via case_id)

**Constraints:**
- case_id is globally unique
- If blocked = True, current_status should be "blocked"
- next_action should always have a value (never empty)
- stage transitions are one-way (see state machine in PHASE 7)

### 2. ExecutionEvent
**Purpose:** Create an immutable audit trail of every state change, decision, and action

**Model Location:** `services/api/app/models/execution_event.py`

**Fields:**

| Field | Type | Required | Default | Purpose |
|-------|------|----------|---------|---------|
| id | Integer | PK | Auto | Unique event identifier |
| case_id | Integer | Yes | - | FK to ExecutionCase |
| event_type | String(50) | Yes | - | Type: intake_created \| classified \| assessed \| routed \| tasks_created \| advanced \| blocked \| unblocked \| closed \| error |
| stage_from | String(50) | No | None | Previous stage (if transition) |
| stage_to | String(50) | No | None | New stage (if transition) |
| action_description | Text | No | None | Human-readable action taken |
| payload_json | Text | Yes | "{}" | JSON details (classification results, assessment data, etc) |
| created_at | DateTime | Yes | now() | Event timestamp |
| actor | String(100) | No | "system" | User/system that triggered event |

**Typical Payloads:**

```json
// classified event:
{
  "classification": "real_estate",
  "confidence": 0.85,
  "parsed_fields": {
    "address": "123 Main St",
    "price": 250000,
    "beds": 3
  }
}

// assessed event:
{
  "estimated_value": 275000,
  "estimated_cost": 85000,
  "estimated_profit": 45000,
  "risk_score": 35,
  "confidence_score": 80,
  "recommended_strategy": "wholesale",
  "missing_fields": []
}

// advanced event:
{
  "from_stage": "assessment",
  "to_stage": "routing",
  "safe_mode": false
}

// blocked event:
{
  "reason": "Confidence too low",
  "threshold_failed": "confidence < 30"
}
```

**Relationships:**
- → ExecutionCase (many-to-one)

**Constraints:**
- Events are immutable (never updated)
- payload_json must be valid JSON
- event_type + stage fields determine semantics

### 4. ExecutionPolicy
**Purpose:** Store conservative policies, buffers, and rules for assessment

**Model Location:** `services/api/app/models/execution_policy.py`

**Fields:**

| Field | Type | Required | Default | Purpose |
|-------|------|----------|---------|---------|
| id | Integer | PK | Auto | Policy identifier |
| domain | String(50) | Yes | - | Domain: cost_buffers \| confidence_rules \| risk_rules \| strategy_mapping |
| policy_type | String(50) | Yes | - | Type: percentage \| absolute \| threshold \| enum_mapping |
| rule_key | String(200) | Yes | - | Rule name (e.g., "arv_buffer_real_estate") |
| rule_value_json | Text | Yes | - | JSON with rule details |
| description | Text | No | None | Human explanation of rule |
| active | Boolean | Yes | True | If false, rule is ignored |
| created_at | DateTime | Yes | now() | Creation timestamp |
| updated_at | DateTime | Yes | now() | Last update timestamp |

**Example Policies:**

```json
// domain: cost_buffers, policy_type: percentage
{
  "rule_key": "arv_buffer_percentage",
  "rule_value_json": {
    "operator": "multiply",
    "factor": 0.85,
    "description": "Reduce estimated ARV by 15%"
  }
}

// domain: cost_buffers, policy_type: percentage
{
  "rule_key": "repair_buffer_percentage",
  "rule_value_json": {
    "operator": "multiply",
    "factor": 1.30,
    "description": "Increase estimated repairs by 30%"
  }
}

// domain: confidence_rules, policy_type: threshold
{
  "rule_key": "missing_address_auto_block",
  "rule_value_json": {
    "field": "address",
    "action": "block",
    "confidence": 0,
    "reason": "Address is required"
  }
}

// domain: risk_rules, policy_type: threshold
{
  "rule_key": "high_risk_threshold",
  "rule_value_json": {
    "risk_score": 85,
    "action": "safe_mode",
    "reason": "Risk score above 85"
  }
}

// domain: strategy_mapping, policy_type: enum_mapping
{
  "rule_key": "profit_to_strategy",
  "rule_value_json": {
    "mapping": {
      "profit_over_50000": "buy_and_hold",
      "profit_20000_50000": "wholesale",
      "profit_under_20000": "arbitrage"
    }
  }
}
```

**Relationships:**
- Used by: assessment_service, routing_service

**Constraints:**
- rule_value_json must be valid JSON
- rule_key must be globally unique per domain
- Only active=True policies are used in calculations

## STATE MACHINE (REFERENCE)

Stages must progress in this order:

```
intake
  ↓ (automatic)
classification
  ↓ (automatic)
assessment
  ↓ (automatic)
routing
  ↓ (automatic)
tasks_created
  ↓ (operator action via /advance)
execution
  ↓ (operator/automation)
closed ← SUCCESS
  ↓ (at any point)
BLOCKED ← can escape back to previous stage
```

Safe transitions checked by `execution_state_service.can_advance(case_id, target_stage)`

## DATABASE SCHEMA CHANGES NEEDED

### New Tables

```sql
-- ExecutionCase
CREATE TABLE execution_cases (
  id SERIAL PRIMARY KEY,
  intake_id INTEGER NOT NULL UNIQUE,
  assessment_id INTEGER,
  case_type VARCHAR(50) NOT NULL,
  route_target VARCHAR(100) NOT NULL,
  current_stage VARCHAR(50) NOT NULL,
  current_status VARCHAR(50) NOT NULL,
  safe_mode BOOLEAN DEFAULT FALSE,
  blocked BOOLEAN DEFAULT FALSE,

  updated_at TIMESTAMP DEFAULT NOW(),

  FOREIGN KEY (intake_id) REFERENCES lead_intake(id),
  FOREIGN KEY (assessment_id) REFERENCES underwriter_assessments(id)

CREATE TABLE execution_events (
  id SERIAL PRIMARY KEY,
  case_id INTEGER NOT NULL,
  event_type VARCHAR(50) NOT NULL,

  payload_json TEXT NOT NULL DEFAULT '{}',

  description TEXT,
```
