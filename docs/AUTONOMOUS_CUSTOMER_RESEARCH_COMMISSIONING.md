## Disposable acceptance

The route group is `/api/prime/customer-research/rehearsal`. It requires the existing Prime key, safe dev/test/sandbox environment, explicit `VALHALLA_CUSTOMER_RESEARCH_REHEARSAL=1`, an authorized Legacy scope and a disposable database. It stays disabled by default, including hosted staging. No outbound adapter is connected.

1. Start an isolated round once with the Prime and owner mandate keys. Set a fixed topic, CAD reference amount, cap and expiry. Three approved fixture topics cover fleet records, contractor quotes and workflow automation.
2. The Prime worker polls `/<round_id>/advance`. It prepares an inbound invitation that discloses automation, then waits for voluntary responses. The rehearsal uses an authenticated private service and a disposable UUID token. It never sends a message. Use `/enroll` with affirmative consent and the exact notice version.
3. The structured Heimdall interviewer asks about recent pain, purchasing authority, effort and stated interest. Early negative or skipped answers end the branch where appropriate. It accepts enumerated answers only and keeps the original token out of journals. This is deterministic AI-led interview orchestration. It has no LLM, recording or free text. A disclosed fixed reference price does not open a purchase.
4. Answer and withdrawal commands are scoped with mutation serialization and safe replay. Withdrawal clears the active answers and suppresses the same token across rounds in that scope. It is accepted while the research stop is active. The withdrawal changes the evidence digest, so a prior review no longer clears a new decision. Existing restricted synthetic aggregate review history remains subject to disposal with the database.
5. Prime queues the exact aggregate through the existing independent Loki service. Loki checks selection bias and misleading willingness-to-pay, fabricated demand and CAC. The relevant Pantheon lenses read only the current study digest and source grade. Independent Loki clearance is required to claim any further reliance. For the demonstration, Prime records **ABSTAIN_PENDING_GENUINE_EVIDENCE**, retaining the independent result digest and objections. No commercial action is selectable.
6. The test covers disabled mode, wrong tenant, missing consent, sequence and exact replay, early termination, enrollment cap, pending and stale review, separately keyed Loki publication, stop, withdrawal and false demand/CAC claims. Delete the temporary database at the end. Never submit live customer information to these routes.

Run from the repository root with the installed development environment active:

```bash
DATABASE_URL=sqlite:// VALHALLA_JWT_SECRET=local-isolated-fixture \
  VALHALLA_OWNER_USERNAME=fixture-owner VALHALLA_OWNER_PASSWORD=internal-fixture-only \
  ENV=dev APP_ENV=dev VALHALLA_EMERGENCY_STOP=true \
  python -m pytest -o addopts='' -qs services/api/tests/test_economic_control.py -k autonomous_customer_research
```

The integration test runs both worker ticks over loopback and prints the independent review and Prime decision proof, with no participant tokens. In a disposable API setup the Prime worker uses `python services/api/tools/cron/customer_research_worker.py --port <port> --round-id <uuid> --scope '<scope JSON>'` and the Prime key in private configuration. Use the existing isolated independent reviewer with the `customer_research` artifact type and separate credentials as exercised by the test. The worker starts no public route, outreach or recurring infrastructure.
