Route Filtering Strategy:
1. System paths - Always allowed: /, /health, /docs, /redoc, /openapi.json, etc.
2. Launch-safe fragments - Allowed by path matching: /api/auth, /api/leads, /api/deals, /api/contracts, /api/eia, etc.
3. Router name matching - Allowed if router name in LAUNCH_ROUTER_NAMES set
4. Feature-locked paths - Blocked unless corresponding feature flag enabled:
   - /api/payments (enable_payments flag)
   - /api/banking (enable_banking flag)  
   - /api/accounting (enable_accounting flag)
   - /api/finops (enable_finops flag)
   - /api/heimdall/auto (enable_heimdall_autonomy flag)

Feature Flags (All Production-Safe Defaults):
- launch_core_only: TRUE (enables route filtering)
- enable_eia_tracking: TRUE (EIA compliance active)
- require_eia_compliance: TRUE (compliance checks required)
- enable_experimental: FALSE (no experimental routers)
- enable_phase2_expansion: FALSE (phase 2 features disabled)
- enable_heimdall_autonomy: FALSE (autonomy locked)
- enable_finops: FALSE (finops locked)
- enable_accounting: FALSE (accounting locked)
- enable_banking: FALSE (banking locked)
- enable_payments: FALSE (payments locked)

New Launch API Endpoints:
- GET /api/launch/status
  Returns: mode, startup checks, feature flags, active router manifest, 
           kept/pruned route counts, route previews

- GET /api/eia/status
  Returns: phase, startup checks, compliance status, monthly report template, 
           red flag summary

- POST /api/eia/check
  Payload: { missing_receipts, unclassified_income, owner_draw, ... }
  Returns: compliance check result, red flags

- GET /api/eia/monthly-report
  Query param: month (optional, defaults to current)
  Returns: generated report with sections
